# Task: Qumulo API Client & Telemetry Integration

## Description
Build Qumulo REST API client with connection pooling, authentication management, metrics fetching (capacity, performance, health, alerts), and Redis caching layer for telemetry data.

## Acceptance Criteria
- [ ] Qumulo REST API client with connection pooling (max 50 connections/cluster)
- [ ] Authentication token caching with 1-hour TTL and automatic refresh
- [ ] Metrics fetching: capacity, performance, health, alerts from Qumulo APIs
- [ ] Redis integration for time-series caching (1-hour retention)
- [ ] Pre-aggregated stats (avg, max, p95) for performance metrics
- [ ] Multi-cluster support with concurrent API requests
- [ ] Rate limiting and exponential backoff for API failures
- [ ] Error handling with graceful degradation when clusters unavailable

## Technical Details
**Implementation Approach:**
- Use Axios or fetch with connection pooling library (e.g., `agentkeepalive`)
- Implement auth token manager with automatic refresh logic
- Fetch metrics from Qumulo endpoints: `/v1/cluster/capacity`, `/v1/cluster/performance`, `/v1/cluster/health`, `/v1/cluster/alerts`
- Redis caching with key pattern: `telemetry:{clusterId}:{metric}:{timestamp}`
- Batch requests for multiple clusters using `Promise.all()`

**Qumulo API Endpoints:**
```typescript
POST /v1/session/login        // Authentication
GET /v1/cluster/capacity       // Capacity metrics
GET /v1/cluster/performance    // Performance metrics (IOPS, throughput, latency)
GET /v1/cluster/nodes          // Node health
GET /v1/cluster/alerts         // Active alerts
```

**Key Files:**
- `src/telemetry/client.ts` - Qumulo API client
- `src/telemetry/auth.ts` - Authentication manager
- `src/telemetry/cache.ts` - Redis caching layer
- `src/telemetry/aggregator.ts` - Metrics aggregation logic
- `src/telemetry/pool.ts` - Connection pool management

**Code Locations:**
- API client: `src/telemetry/client.ts`
- Caching: `src/telemetry/cache.ts`
- Metrics fetching: `src/telemetry/aggregator.ts`
